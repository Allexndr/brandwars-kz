# Глава 4. Маршрутизация: от ситуации к главе Книги 1

*Коротко. Любая задача сначала классифицируется, потом решается. Не наоборот.*
*Сними триггер с запроса, открой главы Книги 1, прогони чек-листы, выдай артефакты этапа.*
*Три главы Книги 1 открываются всегда: критерии продукта, инженерная санитария, дисциплины «сейчас».*
*Ссылка в ответе — только `Книга 1, Глава N, раздел N.M`. Нет раздела — нет претензии «по книге».*
*Конфликт двух глав разрешай матрицей ограничений из состояния, не вкусом модели.*
*Если книга молчит — пометка `вне книги`, диапазон, вопрос человеку. Не выдавай вес модели за playbook.*
*Человеку глава нужна, чтобы ловить прыжок в код и фальшивые ссылки. Агенту — как таблица маршрутов.*

Маршрутизация — фаза между загрузкой (Книга 2, Глава 2) и работой по этапу (Книга 2, Глава 5). Карта знаний говорит, какие файлы есть. Состояние продукта (Книга 2, Глава 3) говорит, что уже решено. Эта глава говорит, какую главу Книги 1 открыть сейчас.

Провал выглядит компетентно. Человек: «сделай API для маркетплейса». Агент выдаёт REST и JWT. Не открыты Книга 1, Глава 5 (чья боль), Книга 1, Глава 14 (контракт как продукт), Книга 1, Глава 32 (модель угроз), Книга 1, Глава 40 (деньги). Текст в репозитории был. Маршрута не было.

Второй провал — открыть соседнюю главу. Триггер «медленно» тянет Книгу 1, Глава 11, хотя узкое место — один SQL без индекса (Книга 1, Глава 18, раздел 18.3; Книга 1, Глава 22, раздел 22.2). Масштаб без профиля нагрузки — карго-культ (Книга 1, Глава 2, раздел 2.6).

Порядок жёсткий: (1) классифицируй запрос и ограничения из состояния; (2) выбери главы и чек-листы; (3) подгрузи тела; (4) реши и запиши артефакт. Запрещён порядок «сначала ответ, потом подберу цитату». Lost in the Middle (Liu et al., 2023) усиливает ошибку, если в контексте вся книга, а якорь триггера не назван.

Команда 1–3: таблица триггеров — весь маршрутизатор; человек утверждает гейт, не выбор главы. 10–30: маршрутизация совпадает с тем, какую дисциплину техлид вызвал бы на ревью (Книга 1, Глава 3, раздел 3.5). 100+: агент маршрутизирует внутри golden path контура (Книга 1, Глава 24, раздел 24.8); выход за контур — вопрос владельцу платформы, не «открыл Главу 11 и пошёл шардировать».

## 4.1. Принцип маршрутизации: любая задача сначала классифицируется, потом решается

Классификация — именованный объект хода, не ощущение. Запиши до первого содержательного совета: триггер, этап из восьми (Книга 2, Глава 5), главы Книги 1, чек-листы, ожидаемый артефакт, что не открывать.

Триггер снимай с глагола человека и с дыр состояния, не только с темы. «Нарисуй микросервисы» при пустых `problem` и `team.headcount` — триггер «архитектура без discovery», не «стиль». Этап остаётся Discovery (Книга 2, Глава 6). «Прод 5xx» при `stage: discovery` — Operations, не продолжение интервью.

Классифицируй по пяти осям. (1) Тип работы: идея, решение, код, инцидент, рост, исследование. (2) Объект: продукт целиком, фича, экран, сервис, данные, деньги, люди. (3) Необратимость: чтение / обратимое изменение / публикация / удаление / платёж. (4) Регуляторика из `constraints`. (5) Срок: час / две недели / квартал — это режим сжатия (Книга 2, Глава 5, раздел 5.5), не смена триггера.

Несколько триггеров в одной фразе — норма. «Собери клон Notion к завтрашнему демо» = продукт с нуля + срок + сравнение с гигантом. Ведущий — самый ранний непройденный гейт плюс самый опасный контур (деньги, ПДн, прод). Остальные — в план, не в первый diff.

`ЕСЛИ классификация не записана, а в черновике уже стек, код или «вот архитектура» → сотри совет, заполни блок маршрута, открой главы блока → проверка: в ответе триггер, этап, список глав до решения.`

`ЕСЛИ человек дал два запроса в одном сообщении («почини 500 и заодно перейди на Kafka») → разведи: инцидент сейчас по Книге 1, Глава 26; смена транспорта — отдельный ADR после стабилизации → проверка: в плане два трека; Kafka не в хотфиксе.`

Когда применять полный блок маршрута: новая сессия, смена этапа, значимое решение, инцидент, просьба «просто сделай». Когда сжимать до одной строки: правка внутри согласованного среза. Цена ритуала — 30–90 секунд. Ошибка: цитата главы, которая не следует из триггера.

## 4.2. Таблица триггеров: запрос пользователя → главы Книги 1 → чек-листы → артефакты

Таблица — рабочий индекс, не энциклопедия. Сначала ведущий триггер, затем обязательные из раздела 4.3, затем ограничения состояния (платежи, AI, UGC, мобилка, realtime). Тела чек-листов открывай на гейте, не из памяти (Книга 2, Глава 2, раздел 2.4).

Идея / «сделай продукт» / «есть задумка». Главы: Книга 1, Глава 4; Глава 5; Глава 6 при намёке на деньги. Чек-листы: 5.8; A.1. Артефакты: problem statement, гипотезы, сжатый PR-FAQ. Не артефакт: репозиторий.

Архитектура / «как устроить» / «нарисуй систему». Главы: 9, 10, плюс тип из 13. Чек-листы: 9.8, 10.8, A.2. Артефакты: расчёт на салфетке, RFC, ADR стиля. Пустые problem/constraints — сначала Глава 5, не 10.

Стек / язык / база / облако. Главы: 16, 9.6, 18.3–18.4. Чек-лист: 16.8 при смене. Артефакты: ADR стека, оценка cost per request (Глава 22, раздел 22.6).

Код / «реализуй» / PR. Главы: 17–20 по слою; 31.10 для 1–3 человек; 23.2 по размеру изменения. Артефакты: diff, тесты, критерий готовности. Нет плана и границ — Книга 2, Глава 8, не прыжок.

Безопасность / логин / «публичная регистрация». Главы: 32, 33; 34 при UGC. Чек-листы: 32.11, 33.9, 34.8. Артефакт: threat model (B.4). JWT из весов без модели угроз — провал маршрута.

Запуск / релиз / «выкатываем». Главы: 23, 25, 31, 32, 33, 39. Чек-листы: 23.9, 25.8, 32.11, 33.9, A.4–A.6. Артефакты: launch plan, rollback, SLO-черновик.

Рост / каналы / «нужны пользователи». Главы: 28, 37, 39; 7 если платный трафик. Чек-листы: 28.9, 39.10, A.8. Артефакты: дерево метрик, план экспериментов. Пустой north_star — сначала 28.1, не закупка.

Инцидент / «прод лежит». Главы: 26, 12; 43.8 при внешней коммуникации. Чек-лист: A.9. Артефакты: роли инцидента, статус, постмортем после стабилизации. Архитектурный рефакторинг в том же diff — запрещён.

AI / LLM / агент в продукте. Главы: 30, 22.6, 32.6 (изоляции), 33.7. Чек-листы: 30.10, A.7. Артефакты: граница автономии, evals, оценка токенов. «Добавь чат» без 30.1 — не маршрут.

Платежи / подписка / маркетплейс-выплаты. Главы: 40, 32, 33, 17.7. Чек-лист: 40.8. Артефакт: схема провайдера, идемпотентность, сверки. Нет 40 в передаче — стоп (Книга 2, Глава 2, раздел 2.8).

API наружу. Главы: 14, 32.4, 22. Чек-лист: 14.8. Артефакты: контракт, лимиты, версия. Внутренний CRUD команды 1–3 — не публичный API.

Мобилка. Главы: 20, 36.5. Чек-лист: 20.8. Realtime / коллаб / медиа. Главы: 21, 13.4–13.7, 22. Чек-лист: 21.8. Данные / аналитика. Главы: 18, 27, 28.3. Чек-лист: 27.8. Миграция / смена стораджа. Главы: 15, 18.7. Чек-лист: 15.7.

UX / онбординг / пустые состояния. Главы: 35, 37; 36 если a11y/i18n. Чек-листы: 35.9, 37.8. Инфра / Kubernetes / «нужна платформа». Главы: 24, 9. Чек-лист: 24.10. Для 1–3 человек Kubernetes обычно красный (24.3).

Команда / найм / процесс. Главы: 8, 41, 42. Чек-лист: 8.12. Агент не нанимает. Покрытие ролей — да.

`ЕСЛИ триггер из таблицы найден, а тела глав нет → работай по toc с пометкой «оглавление, тело недоступно» или останови гейт по 2.8 → проверка: нет пунктов чек-листа из памяти как «Книга 1».`

`ЕСЛИ запрос не совпал ни с одной строкой → классифицируй как «книга молчит» (раздел 4.6), не подгоняй ближайшую главу → проверка: пометка вне книги либо уточняющий вопрос, не фальшивый якорь.`

Применять таблицу к любому продуктному запросу. Не применять к вопросу «что значит термин» без решения: хватит определения и ссылки на словарь / главу. Ошибка таблицы: открыть все строки сразу. Лимит тел — как в Книге 2, Глава 2, шаг 5: не больше семи полных глав.

## 4.3. Обязательные главы, которые открываются всегда, независимо от запроса

«Всегда» значит: якоря в рабочем внимании на каждом значимом ходе, тела — когда срабатывает гейт. Не значит: держать три полных главы в каждом сообщении.

Якорь A. Книга 1, Глава 2. Критерии продукта и запрет карго-культа (разделы 2.1, 2.2, 2.6). Любой совет «как в FAANG» сверяй с 2.6 до выдачи. Пороги latency/uptime — 2.2, не выдуманный SLA.

Якорь B. Книга 1, Глава 3, раздел 3.4. Какие дисциплины включены сейчас. Маршрутизация без этого якоря раздувает scope: к трекеру привычек подтягиваются Главы 11, 21, 29 «на вырост».

Якорь C. Книга 1, Глава 9, раздел 9.8. Инженерная санитария перед дизайном. Срабатывает на любом архитектурном или стековом ходе. Без 9.6 нет права на стиль из Главы 10.

Условные всегда-открытые — по состоянию, не по настроению. Пустые `problem`/`audience` — Глава 5, даже если человек сказал «только стек». `regulation` или ПДн — Главы 32–33 на любом публичном контуре. `stage` релиз или запрос запуска — 23.9, 25.8, 32.11, 33.9. В продукте LLM — 30.10. UGC — 34.8. Деньги пользователей — 40.8. Команда 1–3 — 8.10–8.11 на каждом предложении новой роли или сервиса.

Не всегда-открытые: Главы 11, 15, 21, 29, 41. Их открывает таблица 4.2. Держать «масштабируемость» в фоне на 50 пользователях — антипаттерн 2.6.

`ЕСЛИ значимый ответ ссылается на моду, Google, Kubernetes «для надёжности», но нет якоря 2.6 и размера команды → вставь сверку с 2.6 и 8.10/10.5 → проверка: есть «когда не применять» и цена.`

`ЕСЛИ идёшь в стиль или стек без отметки, что 9.8 открыт или прогнан → останови дизайн, открой 9.8 и сделай расчёт 9.6 → проверка: в RFC есть салфетка; нет голого «возьмём микросервисы».`

1–3: три якоря плюс Глава 5 закрывают 80% маршрутов (порядок величины, оценка по типовым соло-запросам, не бенчмарк). 10–30: добавь 10.8 и 38.2 как фон техлида. 100+: фон задаёт платформа; якорь C может быть чек-листом сервиса, не полной Главой 9.

## 4.4. Как ссылаться на книгу в ответах: формат ссылок и уровень детализации

Формат канонический: `Книга 1, Глава 12, раздел 12.3`. Допустимо сразу чек-лист: `Книга 1, Глава 32, раздел 32.11`. Запрещено: «см. про надёжность», «как в playbook», «Глава про безопасность» без номера. Нет тела — `Книга 1, Глава 32 (оглавление, тело недоступно)`. Вес модели — `вне книги`, не маскируй номером.

Когда ссылка обязательна: стиль, стек, монетизация, ретеншн данных, threat model, SLO, автономия AI, пропуск гейта, отказ человеку. Когда не обязательна: переименование локальной переменной, правка опечатки, статус «сборка зелёная».

Уровень детализации. Один якорь на решение, не простыня. «Модульный монолит, Книга 1, Глава 10, разделы 10.5–10.6, команда 4» достаточно. Пять ссылок без действия — театр. Цитата абзаца — только если человек оспаривает норму; иначе якорь плюс применение к этому продукту.

Не выдумывай подраздел. Если помнишь тему, а номера нет в toc этой сессии — открой `00-toc.md` или пометь вне книги. Ссылка на несуществующий 10.9 при toc до 10.8 — провал усвоения (Книга 2, Глава 2, раздел 2.7, вопрос 1).

`ЕСЛИ в черновике значимое решение без `Книга 1, Глава N, раздел N.M` и без `вне книги` → допиши якорь из открытого файла или пометку → проверка: каждое значимое решение сослано или помечено.`

`ЕСЛИ человек просит «без ссылок, коротко» → сожми форму, оставь якоря на решениях в одну строку «Почему так» → проверка: гейт и номер раздела на месте; нет лекции.`

Команда 1–3: ссылки — для будущего себя и для контроля человека за минуту (Книга 2, Глава 1, раздел 1.5). 10–30: ссылка попадает в RFC/ADR. 100+: ссылка на внутренний стандарт плюс глава книги, если стандарт молчит.

## 4.5. Конфликты между главами и как их разрешать

Конфликт — норма графа дисциплин (Книга 1, Глава 3, раздел 3.3). Разрешай явным правилом, не «сбалансируем».

Правило 1. Ограничения состояния бьют рекомендацию главы «на вырост». Глава 11 тянет шарды. `team.headcount: 3` и нет профиля нагрузки — побеждают 10.5–10.6 и 9.6. Запиши: «11 отложена, revisit_when = 10× текущего RPS по салфетке».

Правило 2. Деньги, закон, безопасность бьют скорость фичи. Глава 37 хочет короткий онбординг. Глава 33 требует основание обработки. Не выкидывай consent молча. Сузь онбординг, оставь минимальное правовое. Не юрист: риск в `risks`, вопрос человеку.

Правило 3. Экономика бьёт рост без модели. Глава 39 предлагает платный канал. Нет юнит-экономики (Глава 7) — канал как эксперимент с потолком бюджета, не как стратегия.

`ЕСЛИ CAC неизвестен, а человек просит масштабировать закупку → не масштабируй, верни к дереву метрик и листу экономики → проверка: нет плана платного канала без потолка бюджета.`

Правило 4. Наблюдаемость и откат бьют выкат. Глава 23.6 хочет canary. Нет 25.8 — сначала сигналы, потом стратегия выката. Иначе canary слепой.

Правило 5. Скучный стек (16.7) бьёт моду (16.2), пока нет constraint человека или измеренного потолка. LLM в продукте (Глава 30) не отменяет 16.7 для остального контура: инновационный бюджет — на модель, не на новый оркестратор.

Правило 6. Человек после предупреждения бьёт обе книги в зоне, где нет закона и необратимости (Книга 2, Глава 1, раздел 1.2). Конфликт «сначала UI» vs Глава 5 — сжатый discovery, не отказ. Конфликт «без threat model в прод с платежами» — стоп до явного принятия риска.

Запись. Конфликт — decision: две главы, кто победил, условие пересмотра. Без записи агент через сессию выберет другую главу.

`ЕСЛИ две открытые главы требуют противоположного (шарды vs монолит, realtime vs cost) → выпиши конфликт, примени правила 1–6, спроси только если цена высокая по 3.7 → проверка: в журнале победитель, проигравшая глава, revisit_when.`

`ЕСЛИ человек настаивает на проигравшей главе без снятия ограничения → назови цену одной фразой, предложи пилот с потолком, не делай вид, что конфликта не было → проверка: риск в YAML; код не реализует оба мира сразу.`

Когда эскалировать человеку: закон, деньги пользователей, неотменяемая граница (Книга 1, Глава 10, раздел 10.1), конфликт двух accepted. Когда решать самому: отложить Главу 11 при трёх людях и неизвестном RPS. Ошибка: «компромисс» — микросервисы «маленькие» плюс общая БД (10.6).

## 4.6. Когда книга молчит: как действовать за её пределами и как это помечать

Молчание — нет главы, нет раздела, нет числа в Приложении C, нет тела при критическом гейте, тема новее книги (закон 2026 года, вендор, протокол). Не молчание: лень открыть файл.

Протокол. (1) Зафиксируй дыру: чего нет. (2) Пометка `вне книги` на решении. (3) Опора: документация вендора с датой, первичка, расчёт порядка величины. (4) Устаревание — Книга 2, Глава 17, раздел 17.3: дата проверки. (5) Предложи человеку дать главу, overlay (Книга 2, Глава 18) или принять риск.

Запрещено заполнять молчание номером похожей главы. Нет главы про конкретный SDK 2026 года — не цитируй 16.6 как будто там этот SDK. 16.6 даёт семейство стека, не версию библиотеки.

Критическое молчание останавливает гейт: нет 32–33 при ПДн/платежах; нет 40 при списаниях; нет 26 при инциденте — туши, но SLO/постмортем не называй стандартом Книги 1. Некритическое: нет 36.4 про motion — сделай скучный UI, `вне книги`.
