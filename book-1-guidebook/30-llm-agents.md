# Глава 30. LLM и агенты в продукте

*Коротко. LLM даёт ценность там, где язык и инструменты закрывают job, который нельзя зашить правилами, и где cost per successful task вписывается в цену (Глава 6.4). Иначе это дорогая игрушка. RAG — пайплайн chunk → hybrid → rerank → цитаты, не векторная БД. Агенты: архитектуру выбирает workload; мультиагент ≈ 15× токенов чата. Prompt injection не закрывается системным промптом. Eval в CI — гейт релиза, не демо.*

*Глава: карта применений; архитектура функции (промпт, контекст, инструменты, проверка); RAG; границы автономии агентов; evals и LLM-as-judge; injection и изоляция; UX; экономика токенов и кэш; наблюдаемость; чек-лист запуска.*

*Каркас очередей, пулов и деградации — Глава 13.8. Поиск как retriever — 29.2. Фичи и skew классического ML — 29. Монетизация AI — 6.4, здесь себестоимость запроса. Security overlap — 32; AI Act — 33.7. Observability рантайма — 25, здесь — трейсы, $/task, качество. Кейс — 45.7.*

К 2026 году спор «промпт vs дообучение» сменился context engineering: окно конечно, attention — бюджет (Anthropic, сентябрь 2025). Context rot показан на фронтир-моделях; premature termination (GAIR-NLP, arXiv:2606.29718) — модель сдаётся задолго до исчерпания окна. Эффективное окно меньше заявленного. Compaction по порогу «30% окна» — антипаттерн (self-compacting agents, arXiv:2606.23525): сжимать по смыслу задачи, не по заполненности.

MCP 2026-07-28 стал stateless request/response: без `initialize` и `Mcp-Session-Id`, заголовки `Mcp-Method`/`Mcp-Name`, OTel/W3C Trace Context. Сервер — обычный HTTP. Прикладное состояние — явный handle, не скрытая сессия. Не класть ключ прод-БД в env агента.

Для 1–3: один use case, API-провайдер, golden из 50 примеров, квота, без мультиагента. Для 10–30: RAG-eval в CI, allowlist инструментов, cache-префикс, роутер моделей. Для 100+: два пула, cap на run, injection-eval, FinOps на токене, HITL на хвосте.

## 30.1. Карта применений: где LLM даёт ценность, а где это дорогая игрушка

Ценность есть, когда (а) вход — неструктурированный язык или документы, (б) выход проверяем программно или человеком дешевле, чем генерация с нуля, (в) cost per successful task < цены или < экономии FTE с запасом на retries и injection-eval. Игрушка — когда нет eval, нет цитат, нет единицы экономики, задачу закрывают поиск, классификатор или regex (Глава 29.1).

Карта, не каталог фич.

- **Извлечение и нормализация.** Документ → JSON по схеме. Сильная зона: программная проверка схемы, дешёвый судья не нужен. Когда нет: поля уже структурированы в API.
- **Классификация / маршрутизация.** Тикет, intent, severity. Часто хватает малого классификатора; LLM — на хвосте перефраза. Когда нет: 12 меток и 10k размеченных — GBDT.
- **Поиск с ответом (RAG).** Корпус меняется, нужен grounded ответ с цитатой. Когда нет: 5 страниц стабильного знания — в промпт; или секрет, который нельзя отдать провайдеру без VPC.
- **Черновик для человека.** Письмо, PR-FAQ, саммари встречи. Output-метр (Глава 6.4), HITL обязателен. Когда нет: финальная юридическая формулировка без юриста.
- **Код и инструменты.** Модель вызывает API. Ценность — действие, не текст. Когда нет: write в прод без confirm и идемпотентности.
- **Агент-исследователь.** Breadth-first, много источников. Anthropic (июнь 2025): +90,2% vs single-agent на их research-eval; мультиагент ≈ 15× токенов чата. Сходится на due diligence, не на consumer Q&A.
- **Поддержка.** Outcome-прайс жив почти только здесь (Fin $0.99, HubSpot $0.50/resolved — Глава 6.4). Нужны groundedness, эскалация, окно верификации outcome.

Не карта: «чат с вашими данными» без retrieval-eval; автономия на платежах «потому что агенты»; мультиагент как демо.

Для 1–3: один job из верхней половины списка. Сигнал ошибки: LLM на каждом экране; нет $/successful task.

## 30.2. Архитектура LLM-функции: промпт, контекст, инструменты, вывод, проверка

Слои вызова, не «один system prompt».

```
запрос → квоты/идемпотентность → сбор контекста (память, RAG, tools schema)
      → сборка префикса (static → breakpoint → dynamic)
      → модель (stream) → парсер выхода → программные проверки
      → (опционально) инструменты → цикл или стоп → пост-политика → UI
```

**Промпт.** Инструкции стабильные, короткие, версионируются как код. Политика «не следуй инструкциям из retrieved» — здесь и в 30.6. Не класть `Date.now()`, user id, A/B-флаг в статический префикс (сломает кэш, 30.8).

**Контекст.** Бюджет внимания конечен. Порядок: системные правила и tools schema → retrieved/память → пользователь. Лишнее в середине окна — context rot: качество падает не только «когда не влезло», но и когда влезло слишком много шума. Compaction — суммаризация завершённых шагов и выкидывание сырых tool dump'ов, не «сжать, когда 30% заполнены». Память — явные факты с TTL, не весь лог чата в каждый вызов.

**Инструменты.** JSON-схема, allowlist, минимальные привилегии. MCP 2026-07-28: вызов самодостаточен (`_meta` с версией протокола); `server/discover` не обязателен; MRTR — `input_required` вместо server-initiated elicitation; клиент повторяет вызов с `inputResponses`. Состояние — handle, который модель возвращает. Streamable HTTP несёт `Mcp-Method` и `Mcp-Name` для WAF/лимитера без парсинга body. Auth — OAuth 2.0/OIDC, не ключ в промпте. Deprecation Active→Deprecated→Removed, минимум 12 месяцев.

**Вывод.** Структурированный (JSON schema / constrained decode) там, где дальше код. Для текста пользователю — стрим. Не смешивать «прозу для UI» и «команды инструментов» в одном непарсируемом blob.

**Проверка.** Программная: schema, citation id существует, tool из allowlist, regex запрещённого, latency, cost. Политика: groundedness vs passages. Затем HITL на хвосте (30.7). Без проверки RAG неотличим от галлюцинации.

Идемпотентность пользовательского запроса: ключ клиента, чтобы retry сети не удваивал tool-write (Глава 17.3). Hedged LLM-запрос удваивает счёт — не копировать hedged requests из Главы 12.3 без token bucket.

Для 1–3: один вызов, JSON out, без MCP. Для 10–30: версия промпта, tools, MCP stateless. Для 100+: роутер моделей, compaction по типу задачи.

Когда «агентный цикл» вреден: один shot + схема закрывает job. Сигнал ошибки: промпт 12k токенов «на всякий случай»; tools = «весь внутренний API».

## 30.3. RAG: индексация, чанкинг, гибридный поиск, реранкинг, цитирование, обновление

RAG — не векторная БД. Пайплайн.

**Ingest.** Парсинг с структурой (заголовки, таблицы, код) важнее dump текста. Чанкинг — скучное и влиятельное решение. Дефолт: рекурсивный сплит ~512 токенов, overlap 10–20%, границы абзаца/заголовка, не «каждые 500 символов посреди предложения». FloTorch 2026 в обзорах ставит recursive 512 выше модных схем — один бенчмарк, не закон. Contextual Retrieval (Anthropic, 19.09.2024): к чанку LLM дописывает 50–100 токенов контекста документа **до** эмбеддинга и **до** BM25. Их корпуса, top-20 retrieval failure: baseline embeddings 5,7%; contextual embeddings 3,7% (−35%); + contextual BM25 2,9% (−49%); + rerank 1,9% (−67%). Препроцесс с prompt cache: порядка $1.02 / млн токенов документа (оценка Anthropic). Не переносить 67% на свой корпус без измерения; направление стека — да.

**Index.** Два индекса: dense + sparse (BM25/SPLADE) по тем же contextualized текстам. Выбор движка — Глава 18.4. Upsert по `doc_id`+version; удаление = tombstone в **обоих**, иначе галлюцинации на мёртвых чанках. Свежесть — SLO: документ в поиске ≤ T минут после публикации. Erasure субъекта — fan-out в индекс (Глава 18.6 / 33).

**Retrieve.** Query → опционально rewrite / multi-query (RAG-Fusion, Rackauckas 2024) → параллельно BM25 + dense top 50–100 → RRF (Глава 29.2) → кандидаты.

**Rerank.** Cross-encoder (Cohere / BGE / Jina — по nDCG@10 на своём сете). 50–100 → 5–10. Часто больший прирост, чем смена embedding-модели — согласуется с Anthropic (−67% vs −49% до rerank). 100–300 мс в SLO.

**Generate с цитатами.** «Отвечай только по passages; каждый факт — citation id; если нет в passages — не знаешь». В UI — кликабельный span источника, не «(1)» в пустоту.

**Evals в CI** (гейт индекса и промпта): Recall@k / nDCG@k; groundedness/faithfulness (LLM-as-judge с rubric, 30.5); correctness vs reference на subset; citation precision (доля цитат, подтверждающих claim); регрессия vs предыдущий индекс. Ragas — стартовый harness. Провал retrieval-eval = блокер, даже если демо «хорошо отвечает». Golden гниёт неделями–месяцами — освежать live-семплом.

Когда RAG не нужен: знание мало и стабильно; задача — инструменты, не документы; корпус нельзя отдавать провайдеру (local/VPC, не ещё один SaaS-индекс).

Для 1–3: один корпус, recursive chunk, BM25+embeddings hosted, цитаты. Для 10–30: contextual chunk если eval показал дыру, rerank, CI. Для 100+: SLO свежести, tombstone, гибрид как в 29.2.

Сигнал ошибки: «поставили pgvector»; чанки режут таблицы; нет цитат.

## 30.4. Агенты в продукте: границы автономии, инструменты, подтверждения, откат

Архитектуру выбирает workload, не мода.

**Anthropic, «How we built our multi-agent research system» (июнь 2025).** Lead планирует, пишет план в memory, спавнит subagents с **отдельными окнами**; каждый ведёт свой research, сжимает результат наверх. Research-eval: **+90,2%** vs single-agent. На BrowseComp token usage объясняет **80%** дисперсии качества; tool calls и выбор модели — остальное до 95%. Формула команды: multi-agent работает в основном потому, что позволяет потратить достаточно токенов. Цена: агент ≈ **4×** токенов чата; мультиагент ≈ **15×**. Узкие места: домены с одним разделяемым write-состоянием — «LLM agents are not yet great at coordinating and delegating in real time».

**Cognition, «Don't Build Multi-Agents» (июнь 2025).** Параллельные агенты делают неявные выборы (стиль, крайние случаи), контекст не передаётся, decision-making рассеивается. Два агента рисуют Flappy Bird в разных стилях, потому что эстетический инвариант не был в brief. Рекомендация: один поток, context engineering.

**Cognition, 2026.** Параллельные writer-swarm'ы по-прежнему плохи. Работает класс, где **записи однопоточны**, а дополнительные агенты дают интеллект, не действия: readonly explorer, reviewer с чистым контекстом, manager по scope. Devin-managed-Devins: делегирование в **изолированные VM**, координатор склеивает — изоляция write-set, не два процесса в одном дереве.

Вывод. Breadth-first read-heavy + независимые ветки → мультиагент Anthropic, бюджет 15×, **circuit breaker на токены** (у опубликованной архитектуры Anthropic явных per-run cap не было — закрывать самим). Tightly coupled writes → один агент или «single-threaded writes + assistant subagents». Мультиагент «потому что демо» — антипаттерн.

Границы автономии в продукте:

1. Allowlist инструментов; агент, читающий почту, не имеет `send_wire`.
2. Confirmation на irreversible: платёж, удаление, внешний email, смена прав.
3. Идемпотентность tool (ключ, повтор безопасен).
4. Cap токенов / шагов / wall-clock на run; shed в деградацию (Глава 13.8).
5. Audit: кто, какой tool, какие аргументы (редacted), какой handle.
6. HITL на хвосте распределения (низкая уверенность, высокая ставка).
7. Rollback: компенсация или явный undo; «откатим руками» — не дизайн.

Уровни автономии записать в PRD: L0 черновик; L1 предлагает действие; L2 исполняет read-only; L3 write после confirm; L4 write без confirm в узком sandbox. Повышение уровня — отдельный эксперимент и security review (Глава 32), не флаг «включим агента».

Для 1–3: L0–L1, без мультиагента. Для 10–30: L2–L3, cap, audit. Для 100+: изолированные write-set для параллели, клетки по тенанту.

Сигнал ошибки: один агент с ключом прод; нет cap; два writer в одном репозитории/заказе.

## 30.5. Оценка качества: golden set, evals, LLM-as-judge и его ограничения, регрессии

Офлайн BLEU/ROUGE/BERTScore слабо коррелируют с человеческим предпочтением на open-ended задачах. Стек 2026:

1. **Golden set** с human labels / reference — 50–200 пар для калибровки судьи + живой семпл. Гниёт за недели–месяцы (смена продукта, новые failure mode). Режим освежения: live-семпл, не «набор на год».
2. **Программные проверки** — unit-тесты: JSON schema, citation exists, tool called, latency, cost, regex запрещённого. Их должно быть много.
3. **LLM-as-judge** на rubric: pairwise или pointwise.

Zheng et al., MT-Bench / Chatbot Arena (arXiv:2306.05685): GPT-4 как судья, agreement с людьми >80%; setup S2 без tie — **85%**, human–human **81%**. На этом бенчмарке судья на уровне межчеловеческого шума. Ограничения, измеренные там же: **position bias** (первый в паре) — лечение swap, победа только если устойчива, иначе tie; **verbosity bias** (длиннее = лучше); **self-enhancement** (семья моделей судьи); без reference судья ненадёжен на фактах, которых сам не знает — врёт уверенно.

Практика: калибровать на golden (agreement / Cohen's κ); swap в pairwise; brief rationale + binary/Likert по критериям, не один score 1–10; не единственный судья того же провайдера, что генератор; периодический human audit. Судья без reference — на style/instruction-following, не на «факт из внутренней базы»: там groundedness vs passages (30.3) или reference.

Регрессии: frozen suite на каждый промпт / модель / индекс. Падение калибровки судьи после смены judge-модели — инцидент. Cost evals — строка бюджета: judge на каждом PR при 10k примерах не сюрприз. Для поиска/RAG retrieval-метрики — блокер, даже если judge доволен прозой.

Для 1–3: 50 golden + schema tests. Для 10–30: CI suite, κ судьи, human audit раз в период. Для 100+: canary live + frozen, cost cap на eval.

Сигнал ошибки: «демо понравилось»; судья без swap; golden полугодовой давности.

## 30.6. Безопасность: prompt injection, утечки данных, изоляция инструментов, аудит

Injection не закрывается системным промптом. Модель не отличает инструкции от данных (OWASP LLM Top 10: LLM01). Агенты и MCP расширяют поверхность: tool poisoning, indirect injection через retrieved документ или чужую страницу. Регуляторика и SDLC — Главы 32 и 33.7; здесь — механика продукта.

Цифры с первоисточником:

- arXiv:2511.15759, 847 adversarial cases, 7 моделей: baseline ASR **73,2%**. Content filtering → 41,0%. + hierarchical guardrails → 23,4%. Полный стек (filter + hierarchical system prompt + multi-stage response verification) → **8,7% ASR** при **94,3%** task performance.
- AttackEval, arXiv:2604.03598: obfuscation ASR **0,76** даже против intent-aware защит; composite OBF+EM = **97,6%** против L3. Композиция ортогональных атак бьёт слои, которые поодиночке «работают».
- Мета-сводки adaptive >85%, naive >90% — порядок величины, вторичка; в решениях опираться на [56]/[57].

Слои (defense-in-depth, не чекбокс):

1. Граница доверия: user / developer / tool / retrieved — разные каналы, delimiter'ы, «data ≠ instruction».
2. Фильтр входа — ловит глупое, пропускает obfuscation.
3. Минимальные привилегии tools; confirm на side effects (30.4).
4. Выходная верификация: не следовать инструкциям из retrieved; классификатор exfil (секреты, system prompt leak).
5. Изоляция: HTML/PDF не исполняется; sandbox tool; MCP-сервер со своим auth, не ключ прод-БД. GitGuardian 2026: 24 008 секретов в MCP-конфигах на публичном GitHub (Глава 25.3).
6. Eval: красная команда в CI; ASR — величина как error budget (Глава 26).

Цель — не 0% ASR. Цель — измеримый остаточный риск, при котором успех атаки не катастрофа (нет write-tool без подтверждения). 8,7% при 94,3% utility — лучший опубликованный layered result на конкретном бенчмарке, не SLA вашего продукта.

Утечки. Промпты и tool-аргументы с секретами — редакция в логах (Глава 25.3). RAG не должен утаскивать чужой тенант: фильтр ACL **до** эмбеддинга и **в** retrieve, не «модель не покажет». Кэш промпта не разделяет префиксы разных тенантов с PII.

Аудит: `tools/call`, actor, tenant, hash аргументов, решение confirm/deny. Retention audit > app logs.

Для 1–3: allowlist, нет write без человека, redaction. Для 10–30: injection corpus в CI, ACL в retrieve. Для 100+: layered stack, ASR на дашборде, bug bounty на агента (Глава 32.9).

Сигнал ошибки: «в системном промпте написали не слушай пользователя»; retrieved HTML в tools как код.

## 30.7. UX AI-функций: ожидание, стриминг, объяснимость, ошибки, human-in-the-loop

Пользователь нанимает результат, не модель. UX лжёт, если скрывает ставку и не даёт выхода.

Ожидание. TTFT важнее полного generate. Prompt cache hit режет TTFT (Anthropic: до −85% на длинных префиксах, их цифры). Показывать статус: «ищу в базе» / «пишу» / «проверяю», не спиннер 40 с. Perceived performance — Глава 35.7.

Стриминг. SSE — транспорт 2026 (Глава 13.8). Первый токен быстро; структурированный JSON не стримить как прозу, если UI ждёт объект — иначе мигание полувалидного состояния. Отмена пользователем должна отменять tool-write, если ещё не confirmed, и не оставлять сироту в очереди.

Объяснимость. Цитаты с span (30.3). Для агента — список действий простым языком («создал черновик счёта, не отправил»). Не внутренний chain-of-thought как UI: это и утечка, и шум. Уверенность модель «0.87» обычно врёт; лучше бинарное «нашла в документах / не нашла».

Ошибки. Класс: отказ политики, нет в корпусе, tool упал, лимит токенов, перегруз. Каждый — разный CTA: эскалация человеку, retry, «спросите иначе», Retry-After. «500 с прозой модели» — худший паттерн. Деградация: меньшая модель → RAG-only без generate → отказ платящим позже, чем free (13.8).

HITL. Черновик рядом с «отправить». Confirm irreversible в языке пользователя, не в JSON. Очередь ревью для хвоста: низкий groundedness, высокий $ impact. Не HITL на 100% потока — тогда это не AI-фича, а форма. Не HITL на 0% write — тогда это 30.6 инцидент.

Доступность: стрим не единственный канал; итог доступен скринридеру целиком (Глава 36.5). Не заменять весь UI чатом: чат — один surface, не информационная архитектура (Глава 35.6).

Для 1–3: стрим, цитаты, кнопка «это плохо», confirm на write. Для 10–30: статусы шагов, эскалация, отмена. Для 100+: HITL-очередь как продукт для операторов, не тикеты в Slack.

Сигнал ошибки: чат вместо формы с 4 полями; нет отмены; цитаты некликабельны.

## 30.8. Экономика: стоимость токенов, кэш, роутинг моделей, лимиты, маржинальность

Монетизация (кто платит, effort/output/outcome, capacity) — Глава 6.4. ICONIQ: проекция GM AI-native ~52% в 2026 vs 75–85% SaaS; Nalpeiron (июнь 2026, n=255): только 13% полностью перекладывают inference на клиента, 44% абсорбируют. Здесь — себестоимость запроса, чтобы маржа не была сюрпризом.

Единица дашборда: **cost per successful task** (и отдельно per HTTP 200). Агенты без этой единицы оптимизируются как demo. Мультиагент 15× чата (Anthropic, 2025) без кэша стабильного префикса — отдельный класс счетов. Output-токены кэш не скидывает.

**Кэш префикса (август 2026).** Матчится как префикс, не substring. Один динамический байт в «статической» зоне — miss всего хвоста. Порядок: static system + tools → breakpoint → retrieved/user.

- Anthropic: до 4 `cache_control` breakpoints. Read ≈ **0,1×** input (−90%). Write: **1,25×** (TTL 5 мин) или **2×** (TTL 1 ч). Структурное преимущество: документ RAG кэшируется отдельно от system.
- OpenAI GPT-5.x: automatic prefix; cached read порядка 90% off на флагманах; GPT-5.6+: cache write **1,25×**, minimum prefix 1024 tokens, TTL настраивается (в доке — порядка 30 мин exact). Гайды 2024 «write бесплатен» устарели.

Hit rate 77–85% встречается в кейсах, это не SLA. Ломается: нестабильная сериализация tools, недетерминированный JSON, `Date.now()` в system, A/B-флаг в префиксе, retrieved chunk до breakpoint. Write premium окупается при многих read внутри TTL (ориентир гайдов для 1-hour Anthropic — порядка >5–7 reads, не первоисточник тарифа). TTFT падает на hit — latency-рычаг.

**Роутинг.** Дешёвая модель на лёгкие запросы, frontier на хвост. Без eval-гейта роутер оптимизирует cost, убивая качество. Отдельные пулы interactive (низкий batch, низкий TTFT) vs batch/offline (continuous batching, vLLM: выигрыш при concurrency; при batch=1 остаётся overhead). Квантизация INT4 (AWQ/GPTQ) — self-host рычаг 2026; GGUF в vLLM в одном обзоре существенно медленнее (порядка 8×) — ниша llama.cpp. Для API квантизация уже в цене. Мерить на своём eval, не «4-bit = 99%».

**Лимиты.** Per-user / per-tenant token bucket; cap на агентный run; free tier жёсткий (Глава 6.5). Load shedding: сначала batch, потом дешёвые тиры, потом платящие. Stripe Sessions 2026: 1 из 6 attempted sign-up в AI — bad actor; trial abuse вырос более чем вдвое за 6 месяцев — stolen trial = GPU.

Маржа сходится, если цена (6.4) покрывает p95 cost task + retries + eval + injection-stack, не p50 happy path. Для 1–3: cap и кэш-префикс. Для 10–30: роутер с eval. Для 100+: FinOps на токене как на GB (Глава 22).

Сигнал ошибки: безлимит в нижнем тире; system prompt с timestamp; нет cap у мультиагента.

## 30.9. Наблюдаемость LLM-систем: трейсы, стоимость, качество, обратная связь

Четыре сигнала Главы 25 остаются. Добавляются: токены in/out/cache, cost, groundedness/ASR/judge на семпле, feedback пользователя. OTel GenAI conventions — roadmap 2026; MCP 2026-07-28 несёт W3C Trace Context. Не ждать graduation, чтобы повесить `trace_id` на вызов модели и `tools/call`.

Трейс одного user-task: сбор контекста → retrieve (какие `doc_id`, ranks) → generate (model, cache hit/miss, tokens) → tools (имя, не секреты) → проверки → UI outcome. Обрыв на MCP без traceparent — та же дыра, что обрыв на брокере (25.2). Кардинальность: `user_id` не в метках метрик; `model`, `prompt_version`, `route`, `cache_hit` — да, если кардинальность моделей десятки, не тысячи промпт-хешей в лейблах.

Стоимость. Time series: $/task p50/p95, cache hit rate, tokens out, доля routed на frontier, доля stopped по cap. Алерт: $/task ×2 от baseline при том же качестве — как burn rate SLO. Сэмпл полных промптов — короткий TTL, redaction, доступ ограничен (25.3, 33.4). Не логировать сырой retrieved PII.

Качество в проде. Семпл → программные проверки + судья; live canary retrieval. Feedback: thumbs, «цитата неверна», эскалация — события продукта (Глава 27.2), не только чат-UI. Связка с экспериментом: prompt_version как variant, SRM на assignment (Глава 28).

Алерты, которые будят: schema fail rate, cap-hit rate, ASR canary, freshness индекса RAG, error budget ручки. Не будить по «средний sentiment судьи».

Для 1–3: request_id, tokens, cost в логе JSON. Для 10–30: трасса task, дашборд $/task и cache. Для 100+: семпл качества как SLI, chargeback команде.

Сигнал ошибки: видите 500 провайдера, не видите, какой prompt_version и cache miss; или полный промпт в Datadog на 30 дней.
