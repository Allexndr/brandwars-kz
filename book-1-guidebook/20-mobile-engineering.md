# Глава 20. Мобильная инженерия

*Коротко. Мобильный клиент — не «фронтенд со стором». Сеть рвётся, часы врут, процесс убивает ОС, релиз идёт через чужой ревью на дни, откат бинарника почти невозможен. Глава даёт критерии стека, слои клиента, офлайн-очередь, бюджеты старта/памяти/батареи/размера, уведомления и релизный контур, который переживает гайдлайны 2026.*

*Читать после Главы 19 (состояние, данные, бандл в браузере) и 13.3 (контракт синхронизации). Транспорт сокета — Глава 21; надёжность очереди и идемпотентность — 11.7 и 12. Сеть и RTT — Глава 9.4.*

*Фаундеру: не выбрать Flutter «потому что одна команда», если продукт — Health Connect и Live Activities. Техлиду: холодный старт и crash-free — ворота стора, не вкусовщина. Staff: kill switch и min version как конфиг, не хардкод.*

*Возвращайтесь, когда стор отклонил билд, когда `onCreate` съел 3 с, когда forced update «на всякий случай» или когда офлайн обещан в сторе, а в коде — retry без `op_id`.*

Мобильная инженерия ломается на четырёх местах, которые веб прощает. Процесс не вечный: ОС убивает фон. Сеть не «медленный HTTP», а часы без канала и смена Wi-Fi → LTE посреди записи. Релиз не `kubectl rollout undo`: ревью Apple/Google — дни, бинарник у пользователя живёт месяцами. Разрешения — одноразовый диалог; сжечь push на первом экране нельзя повторить.

Вторая ошибка — считать кроссплатформу решением найма. На 2026 год три полюса живы: натив, React Native 0.84 (Hermes V1, легаси-архитектура вырезана), Flutter, плюс KMP как «логика общая, UI нативный». Доли рынка в обзорах (RN 35–42%, Flutter ~46%, KMP 23%) — вендорские оценки, не ваш критерий. Критерий — какие API продукта не существуют в общем рантайме и сколько нативных модулей вы обязаны сопровождать после удаления моста.

Третья — оптимистичный UI без журнала операций. После метро пользователь видит дубль заказа. Контракт sync — Глава 13.3; здесь — как этот контракт живёт в SQLite, в фоне и под политикой батареи.

Для 1–3: один стек, SQLite + очередь `op_id`, Crashlytics/Sentry, staged 10%, без своего sync-движка. Для 10–30: feature-модули, Baseline Profiles, бюджет размера и TTID в CI, флаги с сервера. Для 100+: две платформенные команды или явный KMP-контур, vitals как SLO, поэтапная раскатка с halt по crash, политика стора в календарь релизов.

## 20.1. Нативно или кроссплатформенно: решение по критериям, а не по вкусу

Решение — таблица ограничений, не предпочтение языка. Заполните пять строк до ADR.

**Платформенный UI как продукт.** SwiftUI — единственный путь к Liquid Glass «бесплатно» (iOS 26 → правки iOS 27 под читаемость; см. Главу 36 про материал и Reduce Transparency). Material Android — Compose-first. Если визуальный язык и виджеты/Live Activities/Control Center — конкурентное преимущество, натив. Кроссплатформа догоняет с лагом мажорной ОС.

**Железо и фон.** Bluetooth LE, NFC, Health Connect (гранулярные типы Android 16, запрет health-данных для найма и страховки — Play, 2026), геофенс, VoIP push, background processing с лимитами. PWA на iOS: Web Push только у установленного Home Screen PWA с iOS 16.4, без Background Sync/Fetch; установка только Share → Add to Home Screen из Safari. Обещать нативный охват пуша через PWA нельзя: воронка на порядок уже (оценка вендорская; принцип верный).

**Команда.** RN 0.84 (февраль 2026): Hermes V1 по умолчанию, прекомпилированные iOS-бинарники, легаси не входит в iOS-сборку; 0.85 — только Bridgeless. Все нативные модули — TurboModules, все компоненты — Fabric. Фоллбэка нет (кейс «burn the ships»: 0.76 New Architecture default → 0.82 мост удалён). Заявленные цифры Hermes V1 (вендор/вторичные): cold start −29%, память −38%, GC-паузы <12 мс; Shopify — ~10% ускорения старта на Android. Если у вас легаси-модуль без TurboModule — это блокер апгрейда, не «потом». Flutter: Impeller, 60/120 fps, надбавка бинарника порядка 8–12 МБ. KMP стабилен с ноября 2023; рост 7% → 23% за 18 месяцев (вендорская оценка) — шарим домен и сеть, UI остаётся SwiftUI/Compose.

**Общий код с вебом.** RN оправдан, когда экранная логика и TypeScript уже есть (Глава 19). Не оправдан, когда общий код — «кнопка». Flutter не шарит рантайм с React-вебом. KMP не шарит UI.

**Найм и срок.** 1–3 человека с React — RN+Expo быстрее первого стора. 10–30 с двумя сильными нативщиками — KMP или чистый натив, иначе вы получите «общий» слой, который правит один человек. 100+: натив или KMP по доменам; кроссплатформа как оболочка вокруг нативных SDK платежей, камеры, антифрода.

Когда не выбирать натив: CRUD-клиент к API, нет уникальных platform features, один релиз на две платформы важнее пикселя. Чем платите за ранний Flutter/RN: каждым OS-API, который всплывёт через год (Live Activities, Health Connect, Photo picker). Сигнал ошибки: в ADR есть «одна команда», нет списка API, которых нет в общем рантайме.

Сквозной пример. Полевой CRM: офлайн-формы, камера, подпись, редкий фон. 1–3: RN+Expo или Flutter, SQLite, очередь операций. Банк с виджетом баланса, Live Activity перевода и Health-интеграцией: натив или KMP+нативный UI. «Сначала RN, потом перепишем» — двойная стоимость без даты переписывания.

## 20.2. Архитектура мобильного клиента: слои, состояние, навигация, DI

Клиент — три состояния, которые нельзя слить в один Store. UI-состояние (скролл, фокус, черновик поля) умирает с экраном. Кэш серверных сущностей (профиль, лента) переживает экран, инвалидируется по версии/`updated_at`. Журнал операций (то, что ещё не ack) переживает процесс: SQLite/Room/Core Data, не UserDefaults и не in-memory.

Слои, которые держатся на масштабе:

```
UI (SwiftUI/Compose/RN) → use-case / интерактор
  → репозиторий (локальный store + remote)
  → очередь исходящих ops
  → сеть (REST/gRPC + сессионный канал, Глава 21)
```

UI не знает HTTP. Репозиторий не знает навигацию. Очередь не знает пиксели. Нарушение: ViewModel дергает URL и пишет в таблицу — после смены API чините сто экранов.

**Навигация.** Граф маршрутов (NavigationStack / Navigation Compose / RN screens) — единственный источник «где пользователь». Диплинки и push-payload входят в тот же граф, не в отдельный `if notification { openX() }` в AppDelegate. Состояние графа сериализуемо: убийство процесса не должно терять «я был на заказе». Когда не усложнять: пять экранов без диплинков — один coordinator. Когда обязательно: universal links, виджеты, Live Activities — иначе каждый вход плодит новый стек.

**DI.** На Android — Hilt/Koin с графом фичи, не синглтон-бог. На iOS — явная сборка графа в composition root (или TCA Dependency, если команда уже на TCA), не Service Locator из `App.shared`. Цель — тест use-case без UIWindow. Цена: шаблон. Сигнал ошибки: `shared` из ячейки таблицы.

**Границы ошибок.** Сетевой сбой, конфликт sync, 401, порча локальной БД — разные UI. 401 сбрасывает сессию, не ретраит в цикле. Порча БД — миграция или wipe с логом, не «попробуйте позже» бесконечно. Паттерн веб-error boundary (Глава 19.1) здесь — экранный fallback плюс неотправленная очередь, которую нельзя молча дропнуть.

**Модули.** Фича = UI + домен + data этой фичи. Общий `Networking` и `DesignSystem` — да. Общий `AppState` на всё — нет: это глобальная переменная с другим именем. Для 1–3: два слоя (UI + data) достаточно. Для 10–30: фича-модули и запрет import соседней фичи в UI. Для 100+: binary modules / KMP shared, CI на граф зависимостей (как Packwerk на бэкенде, Глава 10).

Когда «чистая архитектура» вредна: команда из двух пишет пять портов на экран логина. Чем платите: неделями проводки. Сигнал: интерфейс на каждый DAO при одной реализации.

## 20.3. Офлайн-first и синхронизация: модели, конфликты, очередь операций

Каркас моделей (LWW / журнал + авторитет сервера / CRDT) — Глава 13.3, не повторяем. Мобильная специфика — процесс умрёт до ack, и ОС не должна быть вашим брокером.

Очередь операций:

1. Пользовательский жест пишет строку `(op_id, type, payload, created_at, status=pending)` в SQLite в одной транзакции с локальным применением (оптимистично).
2. `op_id` — UUIDv7 (RFC 9562). Сервер исполняет effectively-once по ключу (Глава 11.7). Повтор сети — тот же id, не новый.
3. Воркер сети: при появлении канала drain по порядку или по зависимостям (`depends_on`). HTTP 409/422 политики конфликта — не ретраить слепо.
4. Ack: `status=acked`, локальная проекция сверкается с серверным телом. Расхождение — политика из 13.3, не last-write-wins молча.
5. Краш между apply и enqueue невозможен, если это одна транзакция. Краш после send до ack — идемпотентный повтор.

Фон. iOS Background App Refresh и BGTask — квоты, не cron. Android WorkManager — деферрируемые задачи с constraints (сеть, батарея); не держать частичный wakelock «чтобы синкать». Play: excessive partial wake locks 5%; с 1 марта 2026 приложения с чрезмерными wakelock могут терять видимость. Синк в фон — батч, не каждое поле.

Схема. Миграции SQLite версионируются вместе с билдом. Row-level sync (Electric, PowerSync, Zero) превращает миграцию схемы в распределённый раскат: старый клиент не понимает новую колонку. Правило: expand/contract на клиенте как на сервере (Глава 15.4) — новая колонка nullable, старый клиент её игнорирует, min version поднимаете, когда доля старых < порога (смотрите 20.6).

Актор. Ноутбук + телефон + планшет — три writer ID в CRDT, пока не склеите. Склеить по `user_id` наивно ломает uniqueness. Для бизнес-CRUD берите журнал операций, не Yjs: CRDT не знает «баланс ≥ 0». Tombstones и GC — долг с дня 1 (13.3).

Когда не offline-first: каталог, который без сети бесполезен, и вы это написали в UX. Хватит HTTP-кэша и честного empty state. Чем платите за очередь без политики конфликтов: порчей данных через неделю. Сигнал: дубли заказов после двух часов в метро; синка нет, пока приложение на экране.

Для 1–3: Room/Core Data + очередь + идемпотентный API. Для 10–30: PowerSync/Electric, если офлайн в обещании стора. Для 100+: свой sync только если политика конфликтов не закрывается движком.

## 20.4. Производительность: холодный старт, память, батарея, размер приложения

Бюджеты пишутся от порога стора и от устройства mid-range, не от флагмана на кабеле.

**Холодный старт.** Android vitals, TTID (Time To Initial Display), порог «excessive»: cold ≥ 5 с, warm ≥ 2 с, hot ≥ 1,5 с (в части документов Play hot = 1 с — расхождение Google, берите худшее как внутренний red). Это не цель. Практический таргет большинства команд — cold < 2 с на mid-range. Apple: первый кадр < 400 мс (вторичные пересказы HIG), приемлемый старт 1–2 с. TTFD (Time To Fully Drawn) меряйте отдельно через `reportFullyDrawn()`: первый кадр и готовность к тапу — разные вещи.

Главный рычаг Android: `Application.onCreate()` на главном потоке до пикселя. Пять аналитических SDK подряд — каждая миллисекунда у пользователя. App Startup library, ленивая инициализация, Baseline Profiles. iOS: не декодировать тяжёлые ассеты в `didFinishLaunching`; первый кадр — launch screen, не «подождите, грузим конфиг».

**Память.** Jetsam/OOM на фоне — штатный выход. Кэш изображений с лимитом; декодировать под размер view, не full-res. Утечка подписки на notification center / Flow — классика. RN: Hermes V1 снижает память (заявка −38%, вендор); это не разрешение держать всю ленту в JS-хипе. Профиль: Allocations / Android Studio Memory на сценарии «10 минут ленты + фон + возврат».

**Батарея.** Play: excessive battery usage 1%; partial wake locks 5%. Телеметрия: Energy Log, Battery Historian, `JobScheduler` vs вечный foreground service. Запрещено: polling раз в 15 с в фоне; GPS «всегда» без видимой пользователю пользы (Location policy 2026: кнопка геолокации как минимум, геофенс — Geofence API, не foreground service). Радио: батчить сеть; не открывать сокет на каждый экран (Глава 21.1).

**Размер.** Google Play (классическое исследование): +6 МБ APK ≈ −1% install conversion для приложений <100 МБ; −10 МБ на развивающихся рынках коррелирует с ~+2,5% конверсии. Download completion у ~10 МБ примерно на 30% выше, чем у 100 МБ. Контрпример: Flick Solitaire 157 → 74 МБ (−83 МБ), аудитория США, конверсия почти не сдвинулась. Коэффициент — гипотеза для вашего гео, не закон. Психологические пороги: 100 МБ и 200 МБ (лимит загрузки по сотовой). AAB даёт ~15% против универсального APK, до 50% с dynamic feature modules при локалях и ABI. Flutter несёт 8–12 МБ рантайма — заложите в бюджет, не удивляйтесь.

Когда не оптимизировать размер: продукт >100 МБ из-за офлайн-карт, аудитория LTE+ в US/EU, конверсия упирается в скриншоты стора. Чем платите за игнор старта: vitals и органикой. Сигнал: cold 6 с на Android Go, `onCreate` инициализирует шесть SDK.

Для 1–3: убрать синхронные SDK, AAB, измерить TTID на одном mid-range. Для 10–30: Baseline Profiles в CI, бюджет размера как failing check. Для 100+: per-device vitals, динамические фичи, отдельный «lite» при необходимости.

## 20.5. Уведомления: разрешения, сегментация, частота, метрики

Разрешение — продукт, не галочка. Медианы opt-in (Airship-производные, точность условная): Android 81%, iOS 51%, смесь ~60%. CTR: Android 4,6%, iOS 3,4%. Pushwoosh 2025: opt-in по индустриям 23–92% (гиперкэжуал 23% iOS / 69% Android; insurance 70,5% / 91,6%), CTR 0,5–7,4%. Android 13+ тоже спрашивает разрешение; исторический разрыв сужается, но не исчезает.

iOS системный диалог — один раз навсегда. Pre-permission (свой экран «зачем») перед системным. Запрос после ценности, не на первом запуске. Часто цитируемые 68% vs 44% — вендор; принцип момента верный. Категории в настройках: транзакционные / социальные / рекомендации / маркетинг — раздельный opt-out. Тишина по таймзоне пользователя, не офиса.

Частота. Бюджет на пользователя (например ≤3 нетранзакционных в неделю), не на кампанию. Средний американский пользователь ~46 пушей в день — вы конкурируете со всеми. Broadcast CTR в ритейле ~1,3% против ~7,5% у триггерных journey (вендор). Богатая картинка: +2–3 п.п. CTR в большинстве вертикалей — не повод слать промо в Live Activity.

Apple guideline 4.5.3 (июнь 2026): Live Activities нельзя для спама, фишинга и незапрошенных сообщений; только реальное, релевантное, ограниченное во времени событие (доставка, матч, посадка). Нарушение — путь к удалению, не к «креативу».

Метрики кампании: CTR, delivery, opt-out, uninstall. Высокий CTR при всплеске uninstall — убыток. Deep link из пуша обязан попасть в граф навигации (20.2) и не терять контекст при холодном старте.

Когда не слать: «мы не писали две недели». Чем платите за broadcast: opt-out, который не вернуть диалогом. Сигнал: запрос разрешения на splash; Live Activity с промокодом.

Для 1–3: один транзакционный канал, pre-permission, без маркетингового broadcast. Для 10–30: сегменты, quiet hours, dashboard opt-out. Для 100+: частотный cap в реальном времени, holdout на кампании, связь с retention (Глава 37.4), не с CTR.

## 20.6. Релизный цикл: ревью сторов, поэтапная раскатка, форс-апдейт, откат

Деплой веба (Глава 23) и деплой стора — разные машины. Бинарь, прошедший ревью, нельзя «починить конфигом» только если вы заложили флаги и remote config до ревью.

**Ревью.** Apple — очередь и лотерея интерпретации гайдлайнов; закладывайте дни, не часы. Google — быстрее на бинарь, строже на политики данных и разрешений. Срочные security-фиксы имеют ускоренный путь — не используйте его для фичи. Сборка: один артефакт из CI, подпись, дриблинг в TestFlight/internal testing до prod.

**Поэтапная раскатка.** Play staged rollout: 1% → 5% → 20% → 50% → 100% с halt по crash-free и ANR (пороги 20.8). App Store phased release — 7 дней, без вашей тонкой сетки процентов; дополняйте серверным флагом. Метрики halt: user-perceived crash >1,09% overall или >8% на модели (Play vitals); ANR >0,47% / 8%. Не ждать стора: свой RUM на сессии.

**Откат.** Снять билд из staged — да. Забрать бинарь с устройства — нет. Откат = remote flag off + min version не трогать + hotfix в стор. Поэтому флаг важнее «срочного релиза»: выключить фичу без ревью. Kill switch серверный. Минимальная поддерживаемая версия — конфиг. Каждый forced update — гарантированный отток тех, кто не может или не хочет обновиться (нет места, старая ОС, корпоративный MDM).

**Forced update.** Только: критическая уязвимость; ломающий API, который нельзя эмулировать на сервере; юридическое требование. Мягкое: in-app flexible update (Play), баннер (iOS). Жёсткое — блокирующий экран с магазином. Сообщение: почему и что сломается без обновления, не «пожалуйста обновитесь».

Когда не phased: hotfix, который чинит падение 5% сессий — можно ускорить ступени, не прыгать в 100%. Чем платите за force без причины: отзывами и churn. Сигнал: min version поднимают каждую неделю; флагов нет.

Для 1–3: TestFlight/internal, staged 20% на сутки, kill switch. Для 10–30: halt-правила на vitals, календарь ревью. Для 100+: кольца стран/устройств, отдельный процесс expedited review, совместимость N−2 версий клиента.

## 20.7. Специфика платформ и требования сторов, которые ломают планы

Гайдлайны — часть архитектуры. Игнор = сорванный запуск, не «отклонят, поправим иконку».

**Apple, App Review Guidelines 8–9 июня 2026.** Детская безопасность усилена во введении. 1.2: ответственность за нарушающий контент; с 6 февраля 2026 анонимный/случайный чат явно под UGC: фильтр, жалобы, блок пользователей, опубликованные контакты. 4.3(b): Apple может **удалять уже опубликованные** приложения из насыщенных категорий (знакомства, обои, гадания), если неотличимы и не растут. 4.5.3 — Live Activities, см. 20.5. Грубые/повторные нарушения — удаление из App Store и из Developer Program, не только reject билда.

**Google Play, 15 апреля и 15 июля 2026** (минимум 30 дней на соответствие). Contacts: без реальной нужды широкий доступ запрещён — Contact Picker. Location: кнопка как минимум для точной геолокации; геофенсинг убран из одобренных foreground services — Geofence API. Account Transfer: только официальный workflow в Console. Health & Fitness: гранулярные разрешения Android 16, чувствительные типы Health Connect (цикл, алкоголь, симптомы); запрет на решения о найме и страховке. Анонимные чаты не таргетируют детей. Верификация аккаунта без `READ_CALL_LOG` — Digital Credentials API / SMS Retriever. Data Safety: сторонние AI-интеграции и точная/приблизительная геолокация раскрываются. Target API — до 31 августа 2026. Developer verification: незарегистрированные приложения — риск глобального удаления.

**Платежи и аккаунты.** Restore purchases обязателен. Отмена подписки не сложнее оформления (ROSCA / Section 5; Глава 37.7). IAP vs свой биллинг — региональные исключения 2024–2026, юридический контур, не «сэкономим 30%». Не проектируйте единственный путь оплаты, который стор запретит за месяц до запуска.

**Что ломает план на практике.** Запросили Contacts «на всякий случай». Foreground service для геофенса. Live Activity как промо. UGC-чат без модерации и контактов. Анонимный чат с аудиторией 12+. Health-данные в рекламном SDK. Target SDK не обновлён к 31 августа. Перенос аккаунта разработчика «файлом паролей».

Для 1–3: чек-лист разрешений до первой сборки; Data Safety заполнен правдой. Для 10–30: privacy review фичи (Глава 33) до ревью стора. Для 100+: выделенный владелец политик стора, мониторинг рассылок Apple/Play, UGC как в Главе 34.

## 20.8. Чек-лист мобильного релиза

**Стек и архитектура**

- [ ] ADR стека: список platform API, которых нет в общем рантайме; модули — TurboModule/Fabric либо натив.
- [ ] Три состояния разделены: UI, кэш сущностей, очередь ops в SQLite; `op_id` на мутациях.
- [ ] Диплинки и пуш входят в граф навигации; холодный старт из пуша не теряет контекст.

**Качество на устройстве**

- [ ] Cold start < 2 с на оговорённом mid-range; `onCreate`/`didFinishLaunching` без пачки SDK.
- [ ] Crash-free и ANR внутри Play vitals (1,09% / 0,47% overall) на staged.
- [ ] AAB/App Size; порог 100 МБ осознан; dynamic features если локали раздувают бинарь.
- [ ] Нет частичных wakelock вне документированного сценария; батарея в норме vitals.

**Офлайн и сеть**

- [ ] Политика конфликтов записана (13.3); повтор сети не создаёт дубль.
- [ ] Миграции SQLite expand-compatible со старым клиентом либо min version согласован.
- [ ] Таймауты и одноуровневые ретраи с jitter (Глава 12.3); сокет не на каждый экран.

**Стор и раскатка**

- [ ] Разрешения: Contact Picker / Geofence API / Health Connect по факту нужды; Data Safety совпадает с SDK.
- [ ] UGC: фильтр, жалобы, блок, контакты; анонимный чат не на детях.
- [ ] Staged/phased + halt по crash; kill switch и min version с сервера.
- [ ] Forced update только по критерию 20.6; restore purchases и отмена подписки проверены.
- [ ] Target API к дедлайну Play; аккаунт в developer verification.

Для 1–3 достаточно подмножества с пометкой «н/п». Для 100+ пропуск пункта — блокер выкладки.

## Чек-лист главы

- [ ] Стек выбран по API продукта, не по вкусу; PWA не обещает нативный пуш на iOS.
- [ ] Очередь операций и `op_id` есть, если офлайн в UX.
- [ ] Бюджеты TTID, размера, батареи измерены на mid-range, не на флагмане.
- [ ] Push: pre-permission, категории, cap, метрики opt-out/uninstall.
- [ ] Релиз: флаги + staged + kill switch; force — исключение.
- [ ] Гайдлайны июня/июля 2026 прочитаны против вашей поверхности (чат, здоровье, гео, Live Activities).

## Антипаттерны

«Стек по найму — RN без TurboModule, апгрейд 0.84 невозможен — „одна команда“ — ADR по API, иначе натив/KMP»

«Пять SDK в onCreate — cold 5+ с, vitals red — аналитика „с первого кадра“ — App Startup, lazy, Baseline Profiles»

«Офлайн как retry — дубль заказа в метро — нет журнала — SQLite-очередь + op_id (13.3, 11.7)»

«Системный push на splash — opt-in сожжён навсегда (iOS) — маркетинг хочет охват — pre-permission после ценности»

«Live Activity как промо — reject/ban по 4.5.3 (июнь 2026) — второй канал пуша — только живое событие»

«Force update каждую неделю — churn, 1★ — „все на последней“ — флаги; force только CVE/ломающий API/закон»

«Contacts и CALL_LOG на всякий случай — отклонение Play 2026 — скопировали манифест — Picker и SMS Retriever»

«PWA вместо приложения — нет фона и пуша на iOS — экономия стора — честный web; натив если фон/пуш — продукт»

«Общий AppState — гонки, бог-объект — как Redux на всё (19.4) — UI / кэш / очередь раздельно»

«Wakelock чтобы синкать — потеря видимости с 1.03.2026 — „надёжная доставка“ — WorkManager/BGTask, батч»

«Размер не меряем — падение install в IN/BR — „у нас США как Flick“ — бюджет AAB; коэффициент +6 МБ проверять на своём гео»

«Отмена подписки в лабиринте — FTC/ROSCA, стор — retention треннием — отмена ≤ оформления (37.7)»
