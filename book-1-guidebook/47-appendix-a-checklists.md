# Приложение A. Мастер-чек-листы

Сжатые чек-листы для повторного использования. Детали и пороги — в главах. Пункт без владельца не считается выполненным. Даты актуальности цифр — Приложение C.

## A.1. Discovery

- [ ] Сегмент назван так, что кого-то вычеркнули (Глава 5.1).
- [ ] JTBD: работа, обстоятельства, критерий успеха; не «нужен наш продукт».
- [ ] 8–12 проблемных интервью без питча; цитаты, не интерпретации.
- [ ] Гипотеза: тезис, эксперимент, kill metric, дата, владелец.
- [ ] Метод проверки соразмерен риску: fake door / concierge / WoZ / пилот (5.5).
- [ ] MVP не начат, если гипотеза ещё «в голове» (5.6).
- [ ] Признаки PMF названы заранее, не после роста трафика (5.7).
- [ ] PR-FAQ ≤1 стр. языком клиента (Глава 4).
- [ ] Салфетка экономики: хотя бы порядок LTV/CAC и cost per use (7, 9.6).
- [ ] Семь полей кейса заполнены начерно (45.1).
- [ ] Список «не строим в 30 дней» записан (46.1).
- [ ] Регулятор/PII/платежи: минимум данных, не «потом counsel».

## A.2. Архитектурное ревью

- [ ] Неотменяемые решения перечислены; цена изменения названа (10.1).
- [ ] Bounded contexts и ключ изоляции в каждой таблице критического пути (10.2, 45.1).
- [ ] Стиль выбран матрицей: команда, домен, нагрузка, регулятор, срок (10.5).
- [ ] Нет распределённого монолита: деплой и отказ не общие «случайно» (10.6).
- [ ] Согласованность по 5 операциям записана (не «мы AP»).
- [ ] Деградация на отказ каждой hard-зависимости (12.4).
- [ ] Единица стоимости: запрос / GB / тик / токен (13.1, 22.6).
- [ ] Cross-AZ и fan-out учтены в бюджете latency и $ (9, 11, 22).
- [ ] ADR в репозитории; fitness functions названы (10.7).
- [ ] План 10× нагрузки: что сломается первым (11.10).
- [ ] Деньги и IAM не в том же SLA, что лента/поиск.
- [ ] Лицензии deps (AGPL/BSL/SSPL) просмотрены (44.6).

## A.3. Production readiness

- [ ] SLO/SLI на пользовательский симптом; error budget и политика (26.1–26.2).
- [ ] Дашборд до релиза; алерты **сработали** на стейдже.
- [ ] Runbook на типичные отказы; on-call знает о выкате.
- [ ] Откат выполнен хотя бы раз, не только описан.
- [ ] Миграция expand/contract или forward-fix; бэкап с restore.
- [ ] Feature flag / kill switch проверен.
- [ ] Секреты в vault; новые эндпоинты с authn/authz; SCA без unfixed critical.
- [ ] Ёмкость: нагрузка на профиле пика; rate-limit; graceful downstream.
- [ ] Логи структурированы; trace на новом пути; PII не в логах.
- [ ] Документация пользователя и changelog обновлены.
- [ ] Поддержка: макросы, обучение, named go/no-go (43.9).
- [ ] Для AI: evals смоук, лимит токенов, halt инструментов (30.10, A.7).

## A.4. Релиз

- [ ] Acceptance закрыты; S1/S2 на релизном флоу нет либо приняты письменно.
- [ ] Diff coverage / быстрый набор зелёный; флейки не лечатся `retries: 3` без тикета.
- [ ] Canary по метрикам, не по таймеру; сегмент не бьёт одного крупного клиента.
- [ ] Флаг нового; план уборки флага.
- [ ] Миграция двусторонняя на время раскатки.
- [ ] Мобильный: staged rollout / стор-ревью / форс-апдейт если нужен (20.6).
- [ ] Нет тотального freeze: риск-скоринг вместо склада диффов (Meta 2023).
- [ ] Владелец go / reduced-scope / hold назван.
- [ ] Пост-релиз: смоук в проде, окно наблюдения, откат не дольше, чем умеете.
- [ ] Версия доков = версия продукта (43.4).

## A.5. Безопасность

- [ ] Модель угроз на логин, оплату, загрузку, агентные инструменты (32.1).
- [ ] Authn: passkeys/MFA, сессии, восстановление — не «пароль в БД».
- [ ] Authz: явная модель; fail-closed; аудит прав.
- [ ] Секреты не в git; ротация; KMS на чувствительное.
- [ ] Готовая крипта, не своя.
- [ ] Цепочка поставки: lockfile, SBOM, подпись артефакта где критично.
- [ ] Ворота CI: secrets → SCA → узкий SAST; блок только validated high/critical.
- [ ] Пентест/bug bounty с владельцем фиксов, не PDF в ящике.
- [ ] Детект и план утечки (32.10); GDPR 72 ч если ПДн (33).
- [ ] CHD/SAD не хранятся; hosted checkout (40, PCI 4.0.1).
- [ ] Агенты: injection, изоляция инструментов, audit (30.6).

## A.6. Privacy

- [ ] Инвентарь ПДн: типы, основание, срок, место.
- [ ] Минимизация: поле, которого нет в job, не собирается.
- [ ] Доступ / экспорт / удаление реализуемы технически, включая бэкапы и очереди (33.3–33.4).
- [ ] Трансграничка и residency: ADR, не надежда на регион «us-east-1».
- [ ] Согласия и трекинг: не класть рекламный SDK туда, где платежные поля.
- [ ] DPA и subprocessors (облако, PSP, LLM, support tools) актуальны.
- [ ] Промпт внешнего LLM не содержит того, что DPA запрещает.
- [ ] Retention логов и аналитики назван; «навсегда» = находка аудита.
- [ ] Privacy-ревью фичи до выката, не после жалобы.

## A.7. Запуск AI-функции

- [ ] Задача не решается правилами дешевле (29.1, 30.1).
- [ ] Спека поведения и golden set 50–200; regression ≠ gold.
- [ ] Детерминированные проверки отдельно от LLM-as-judge.
- [ ] Пин модели, промпта, температуры, схемы; судья пиннится отдельно.
- [ ] Промоушн парный vs прод; не абсолютный скор.
- [ ] Смоук evals в PR; полный набор на merge; блок по регрессии.
- [ ] Лимиты, кэш, роутинг, cost per request на дашборде.
- [ ] Hold кредита / cap до инференса, если COGS переменный.
- [ ] Инструменты с сайд-эффектом: confirm, идемпотентность, откат.
- [ ] Threat model: injection, утечка, чрезмерная автономия.
- [ ] UX: стрим, ошибка, отказ, HITL (30.7).
- [ ] Trial abuse: карта, Radar/аналог, device binding, не открытый GPU.
- [ ] Risk lane ревью; человек Accountable за «готово».

## A.8. Go-to-market

- [ ] Петля роста названа; канал не «везде сразу» (39.1–39.2).
- [ ] Позиционирование: отсекающая фраза и альтернатива клиента (4, 39.3).
- [ ] Packaging и цена совместимы с COGS (6, 7); AI не спрятан в flat.
- [ ] PLG vs sales: ICP и ACV согласованы (39.5–39.6).
- [ ] Запуск: волны, площадки, поддержка обучена, статус-страница (39.7, 43).
- [ ] Docs: TTFV измерен на новом человеке.
- [ ] Атрибуция: опрос «как узнали»; не только last-click.
- [ ] Международное: метод оплаты и налог страны плательщика (40, 39.8).
- [ ] ToS: автопродление, смена цены, AUP.
- [ ] Kill criteria кампании/фичи запуска записаны.

## A.9. Инцидент

- [ ] IC, Comms, Scribe, Ops назначены; IC ≠ Comms на P1 (26.4, 43.8).
- [ ] Severity и пользовательское влияние названы точно.
- [ ] Апдейт из 4 пунктов; **Next update by**; P1 каждые 15–30 мин.
- [ ] Сначала митигация (флаг, откат, shed), потом причина.
- [ ] Статус-страница — единая точка правды; макрос поддержке сразу.
- [ ] Только проверяемые факты; нет ETA наугад.
- [ ] Таймлайн со штампами для постмортема.
- [ ] Внутренний разбор ≤24 ч; внешний 24–72 ч если публичный.
- [ ] Action items: владелец, срок; иначе ритуал.
- [ ] Error budget: решение стоп-фич по политике, не по настроению.
- [ ] Утечка: регулятор в срок; CHD — отдельный класс.

## A.10. Годовое ревью

- [ ] Профиль зрелости 10×5 с фактами (2.4, 46.5).
- [ ] Runway, burn multiple, Rule of 40 с фиксированным определением (44.1).
- [ ] CAC payback vs runway; NRR; concentration клиентов и вендоров.
- [ ] Реестр рисков: владельцы, сигналы, корреляции, pre-mortem распарсен (44.3–44.4).
- [ ] Плейбуки: PSP lockout, key person, утечка, касса, санкции.
- [ ] Bus factor ≥2 на billing/DNS/root; restore ≤90 дней.
- [ ] License/SBOM; Redis/Valkey и BSL-зависимости названы.
- [ ] 15–20% ёмкости на долг; клоны в CI.
- [ ] DORA+очередь ревью+CFR себя к себе, не elite-OKR (42.9).
- [ ] Dual-track IC жив; junior-пайплайн не вычеркнут молча (41).
- [ ] Сертификации vs спрос, не коллекция PDF.
- [ ] Список Hold в техрадаре; список «сознательно не делаем».
